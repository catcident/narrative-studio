## 사용 방법

### LLM A 단독 테스트 (엔티티/관계만)

```bash
cd test

# 특정 테스트
npx tsx run-test.ts 01 02 03

# 전체 테스트
npx tsx run-test.ts all

# 출력 디렉토리 지정
npx tsx run-test.ts all --outdir results8
```

### LLM A+B 통합 테스트 (로어북 포함)

```bash
cd test

# 특정 테스트 (번호로)
npx tsx run-lorebook-test.ts 01 02 L01 L02

# 전체 테스트
npx tsx run-lorebook-test.ts all

# 출력 디렉토리 지정
npx tsx run-lorebook-test.ts all --outdir lore-results-v3

# 실제 소설 데이터 테스트 (data/ 폴더의 .md 파일들)
npx tsx run-lorebook-test.ts data

# 파일 직접 지정
npx tsx run-lorebook-test.ts /path/to/file.txt
```

### 테스트 결과 확인

결과 JSON 파일은 지정된 출력 디렉토리에 저장됨. 각 JSON에는:
- LLM A 결과: entities, relationships, scenes
- LLM B 결과: lore_entries (카테고리별 인물 프로필, 세계관 설정)
- 자동 채점: 100점 만점, 8개 평가 항목

---

## 채점 시스템 (100점 만점)

| 항목 | 배점 | 설명 |
|------|------|------|
| 주인공/인물 커버리지 | 20 | KG 엔티티 대비 로어 보유 인물 비율 |
| 카테고리 다양성 | 15 | appearance, personality, ability 등 카테고리 종류 |
| 중복 없음 | 15 | 동일 (엔티티, 카테고리, 장면) 내 유사 내용 중복 |
| 장면 매핑 | 10 | LLM B 장면번호 → KG sceneId 매핑 성공률 |
| 세계관/lore | 10 | 비인물 엔티티(조직, 아이템 등) lore 엔트리 |
| 대명사 resolve | 10 | "나"/"그" 대명사 → 실제 이름 변환 |
| 엔트리-엔티티 연결 | 10 | 로어 entityName이 KG 엔티티와 매칭 |
| 충분한 추출량 | 10 | 텍스트 분량 대비 적절한 엔트리 수 |

## 검증 체크리스트

### LLM A (엔티티/관계)
- [ ] chapter/scene이 올바르게 인식되는가
- [ ] 엔티티가 누락 없이 추출되는가
- [ ] 같은 엔티티가 다른 이름으로 분리되지 않았는가 (LLM 병합 검토)
- [ ] 다른 엔티티가 잘못 합쳐지지 않았는가 (특히 "나"/"그"/"그녀")
- [ ] 세대/계층 소속 관계가 올바른가
- [ ] 관계 타입이 올바른가

### LLM B (로어북)
- [ ] 주인공이 가장 많은 로어 엔트리를 가지는가
- [ ] 카테고리가 다양하게 분포되는가 (personality 편중 없음)
- [ ] 1인칭 "나"가 실제 이름으로 변환되었는가
- [ ] 세계관 설정이 lore 카테고리로 추출되었는가
- [ ] 중복 엔트리가 없는가
- [ ] 장면 매핑이 정확한가
