## 공통 문제 (전 테스트)

### 1. 자동생성 동시등장 관계 폭발 (심각도: HIGH)

| 테스트 | 의미있는 관계 | 자동생성 관계 | 비율 |
|--------|-------------|-------------|------|
| 01 | 9 | 20 | 69% 노이즈 |
| 02 | 15 | 29 | 66% 노이즈 |
| 03 | 14 | 29 | 67% 노이즈 |
| 04 | 21 | 35 | 63% 노이즈 |
| 05 | 30 | 36 | 55% 노이즈 |
| 06 | 11 | 20 | 65% 노이즈 |
| 07 | 43 | 253 | **85% 노이즈** |

**문제**: `inferCoOccurrenceEdges`와 `inferDescriptionBasedEdges` 함수가 같은 장면에 등장하는 모든 엔티티 쌍에 대해 관계를 생성. 캐릭터가 많은 장면에서 O(n²) 폭발.

**잘못된 관계 유형**: 동시등장으로 생성된 관계에 "소유" 타입이 부여되어 의미적으로 완전히 틀린 관계가 대량 생성됨.
- 예: 마물 "소유" 연습용 검, 김 사장 "소유" 캔버스

### 2. firstMention.chapter 항상 1 (심각도: MEDIUM)

모든 엔티티의 `firstMention.chapter`가 1로 고정. 2화나 3화에서 처음 등장하는 엔티티도 1화로 표시됨.

**원인**: `buildKnowledgeGraph`에서 엔티티 생성 시 `firstMention: { chapter: 1 }`로 하드코딩.

### 3. importance 값 미분화 (심각도: LOW)

모든 엔티티의 importance가 5로 동일. 주인공과 소품의 구분이 없음.

### 4. description 중복 텍스트 (심각도: LOW)

청크 병합 시 같은 설명이 반복 추가됨. 예: "A반 반장, 성실함 A반 반장, 성실함, 연극 주연"

**원인**: `mergeExtractions`에서 description 병합 시 `includes()` 체크가 부분 문자열만 확인하여, 기존 텍스트가 새 텍스트의 앞부분과 동일해도 중복 추가됨.

### 5. "나" 처리 미흡 (심각도: HIGH - 특정 케이스)

1인칭 자동 통일 코드는 제거했지만, LLM이 여전히 "나"를 단일 엔티티로 추출. 시점 변경 소설에서 다른 화자의 "나"가 합쳐짐.

## 개선 권장사항

### 즉시 수정 필요 (HIGH)

1. **동시등장 관계 생성 제한**: `inferCoOccurrenceEdges`에서 캐릭터 간에만 생성하거나, 한 장면당 최대 관계 수를 제한하거나, 이 기능을 아예 비활성화. "소유" 타입 자동 부여도 수정 필요.

2. **"나" 처리 프롬프트 추가**: USER_PROMPT에 1인칭 화자 처리 규칙 추가 - "시점이 바뀌면 '나'를 별도 엔티티로 추출하거나, 실제 이름이 있으면 이름으로 추출"

### 중기 개선 (MEDIUM)

3. **firstMention 정확도**: 엔티티가 처음 등장하는 실제 장면/챕터 번호를 기록

4. **챕터 인식 강화**: 프롤로그/에필로그 및 특수 형식 챕터 인식 개선

5. **description 중복 제거**: 병합 시 기존 설명과 새 설명의 중복 부분을 더 정교하게 체크

### 장기 개선 (LOW)

6. **importance 자동 계산**: 등장 장면 수, 관계 수 기반으로 importance 자동 산정

7. **카테고리 정확도**: organization 카테고리 추가 또는 프롬프트에서 조직/집단 처리 규칙 강화
