## 3. 연속 마크업 수식

### 3-1. 로그 보간 함수

모델의 청크 원가에 따라 마크업을 연속적으로 산출한다. 이산 티어 경계가 없으므로 **크레딧 역전(저가 모델이 고가 모델보다 비싼 현상)이 구조적으로 불가능**하다.

```
markup(model) = MAX_MARKUP − (MAX_MARKUP − MIN_MARKUP) × t

여기서:
  t = log(chunk_cost / COST_MIN) / log(COST_MAX / COST_MIN)
  t ∈ [0, 1]  (COST_MIN 이하 → 0, COST_MAX 이상 → 1)
```

**로그 보간을 사용하는 이유**: 모델 원가가 46배(Flash Lite $0.00070 → Sonnet $0.03252) 범위로 분포하므로, 선형 보간 시 저가 모델 4종이 거의 동일한 마크업을 받게 됨. 로그 보간은 저가 영역에서 마크업 차이를 확대하여 모델 간 가격 차별화를 보존.

### 3-2. TypeScript 구현

```typescript
function calculateMarkup(chunkCostUsd: number): number {
  if (chunkCostUsd <= COST_MIN) return MAX_MARKUP;
  if (chunkCostUsd >= COST_MAX) return MIN_MARKUP;

  const t = Math.log(chunkCostUsd / COST_MIN) / Math.log(COST_MAX / COST_MIN);
  return MAX_MARKUP - (MAX_MARKUP - MIN_MARKUP) * t;
}
```

## 4. 세션 일괄 차감 수식

### 4-1. 기본 수식

```
session_credits = max(1, ceil(total_session_cost_usd × calculateMarkup(chunk_cost) × USD_TO_KRW / KRW_PER_CREDIT))
```

여기서:
- `total_session_cost_usd` = 추출 비용 합계 + 선별(selector) 비용 합계
- `calculateMarkup(chunk_cost)` = 추출 모델의 청크 원가에 기반한 연속 마크업
- `USD_TO_KRW` = 1500
- `KRW_PER_CREDIT` = 10

> **참고 — selector 비용과 마크업**: selector(Gemini Flash, ~$0.0005/call)의 원가는 세션 전체 비용에 포함되며, 추출 모델의 마크업이 일괄 적용됨. 따라서 고가 모델(5.0x) 사용 시 selector 비용에도 5.0x만 적용되어, 고가 세션의 총 마크업이 약간 낮아짐. 이는 **의도된 설계**로, 고가 모델의 크레딧을 더 합리적으로 만들어 프리미엄 사용을 유도함.

### 4-2. 세션 비용 산정

```
total_session_cost_usd = (N × extraction_cost_per_chunk) + ((N-1) × selector_cost_per_call)
```

- `N` = 총 청크 수 = ceil(문서_길이 / 5000)
- `extraction_cost_per_chunk` = 모델별 단가 (Section 3-3 테이블)
- `selector_cost_per_call` ≈ $0.0005 (Gemini Flash 사용, 고정)

### 4-3. 청크별 차감과의 차이

| 항목 | 청크별 차감 | 세션 일괄 차감 (확정) |
|------|------------|---------------------|
| 올림 횟수 | N회 (청크당 1회) | **1회** (세션당 1회) |
| 올림 오차 | 큼 (저가 모델에서 누적) | **최소** |
| 사용자 경험 | 크레딧이 불규칙하게 감소 | **분석 시작 전 정확한 비용 표시** |
| 중간 중단 시 | 소비된 청크만큼만 차감 | 사전 예약 후 완료 시 확정 (아래 참조) |

**예시 (Flash, 100K 텍스트, 20청크):**
- 청크별: ceil(0.00093 × 9.63 × 150) = 2cr × 20 + ceil(0.0005 × 9.63 × 150) = 1cr × 19 = **59cr**
- 세션별: ceil(0.0281 × 9.63 × 150) = **41cr** (31% 절감!)

### 4-4. 중간 중단 처리

```
분석 시작 시:
  1. 예상 크레딧 산정 (session_credits)
  2. 잔액에서 예약 (reserve)
  3. 분석 진행

분석 완료 시:
  → 예약된 크레딧 확정

분석 중단 시 (잔액 부족/사용자 취소):
  → 실제 처리된 청크 기준으로 재계산
  → 차액 환불 (reserved - actual)
```

### 4-5. 채팅 과금

채팅은 세션 기반이 아닌 **메시지별 차감** 유지. 동일한 연속 마크업이 적용됨.

```
message_credits = max(1, ceil(message_cost_usd × calculateMarkup(model_chunk_cost) × USD_TO_KRW / KRW_PER_CREDIT))
```

- 컨텍스트 윈도우 확장에 따라 장기 대화 시 메시지당 비용 증가 (`MAX_HISTORY_CHARS = 45,000`)
- Free 플랜: 분석당 3회 제한으로 비용 통제
- 채팅 비용은 분석 크레딧과 동일 풀에서 차감

### 6-5. Credit-First BYOK (Pro 이상)

개인 OpenRouter API 키를 등록한 사용자가 구독 크레딧과 BYOK를 자동 전환하는 기능.

**기본 모드 — 크레딧 우선 (Credit-First)**:

```
1. 구독 크레딧 잔액 > 0  →  크레딧 차감 (일반 과금)
2. 크레딧 잔액 = 0       →  자동으로 개인 API 키로 전환
3. 전환 시 사용자에게 알림  →  "크레딧 소진됨 — 개인 키로 분석 중"
4. 월 구독 갱신 시         →  다시 크레딧 우선 모드로 복귀
```

**수동 모드 — 항상 BYOK**:
- 설정에서 "항상 개인 키 사용" 토글
- 구독 크레딧이 남아있어도 개인 키만 사용
- 크레딧은 채팅 등 다른 용도에 보존

**설계 의도**:
- 크레딧 소진 = 서비스 중단이 아닌, BYOK로 자연스러운 전환
- "이번 달 크레딧 다 썼는데 분석할 것이 남았다" → 패키지 구매 또는 BYOK 중 선택
- BYOK 사용 시 서버 LLM 비용 0 → 서버는 인프라 비용만 발생

### 11-4. 리텐션 전략 (추가 크레딧 구매 유도)

**1. 소프트 캡 (Soft Cap)**
- 크레딧 0 도달 시 현재 진행 중인 분석은 완료 허용, 신규 분석만 차단

- 사용자 심리: "끊기지 않아서 좋다" → 서비스 신뢰 → 추가 구매

**2. 3단계 잔액 알림**
- 75% 소진: "잔여 200cr — 이번 달 분석 계획을 세워보세요"
- 90% 소진: "잔여 80cr — 패키지로 크레딧을 추가하세요"
- 100% 소진: "크레딧 소진 — Pro 업그레이드 또는 패키지 구매"
- Kahneman & Tversky (1979): 손실 회피 효과 — 잃을 것이 있을 때 행동 동기 2배

**3. 자동 리로드 + 10% 보너스**
- 잔액 임계치(예: 50cr) 이하 시 설정된 패키지 자동 구매
- 자동 리로드 설정 시 **+10% 보너스 크레딧** (S: 550→605, M: 1,200→1,320, L: 2,800→3,080)
- Starbucks 자동 충전 모델: 미국 매출 60%가 Rewards 회원

**4. 첫 패키지 구매 보너스 +50%**
- 최초 1회 패키지 구매 시 크레딧 50% 추가 (S: 550→825, M: 1,200→1,800, L: 2,800→4,200)
- Nunes & Dreze (2006) 부여된 진전 효과: 사전 시작된 목표의 완료율 34% vs 19%
- "이미 충전했으니 쓰자" 심리 유도

**5. 누적 보상 (Pro 이상)**
- 분기 내 패키지 3회 구매 시 다음 패키지 +20% 보너스
- 반복 구매 습관 형성 → LTV 증가

**6. 시즌 프로모션**
- 분기별 이벤트: 특정 기간 패키지 구매 시 +30% 보너스
- 구독 전환과 연계: "이벤트 기간 Pro 가입 시 첫 달 +500cr 보너스"
