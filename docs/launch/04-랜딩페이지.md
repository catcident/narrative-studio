# 04. 랜딩 페이지 설계

> storygraph.catcident.com 미로그인 사용자를 위한 랜딩 페이지

## 현재 상태

- 랜딩 페이지 없음 (SPA 전용)
- `/login` 페이지만 존재 (최소한의 인증 UI)
- 미로그인 시 자동으로 `/login`으로 리다이렉트

## URL 구조 제안

```
storygraph.catcident.com/           → 랜딩 페이지 (미로그인 시)
storygraph.catcident.com/app        → 앱 SPA (로그인 후, 현재 page.tsx)
storygraph.catcident.com/login      → 로그인 페이지 (기존)
storygraph.catcident.com/pricing    → 가격 페이지 (선택, 랜딩에 포함 가능)
```

또는 단순하게:
```
storygraph.catcident.com/           → 로그인 상태면 앱, 아니면 랜딩
storygraph.catcident.com/login      → 로그인
```

## CTA 배치 전략

| 위치 | CTA | 타입 |
|------|-----|------|
| 헤더 (sticky) | "시작하기" 버튼 | 스크롤 시 고정 |
| Hero | "무료로 시작하기" + "데모 보기" | 주/보조 듀얼 |
| 기능 섹션 후 | "내 소설 분석하기" | 맥락적 |
| 가격 섹션 | 플랜별 시작 버튼 | 전환 포인트 |
| 페이지 하단 | "무료로 시작하기" | 마지막 포착 |

**CTA 텍스트 원칙**:
- 1인칭 사용: "내 소설 분석하기" (O), "분석 시작" (X)
- 구체적 행동: "무료로 시작하기" (O), "더 알아보기" (X)
- 부담 낮추기: "신용카드 없이", "30초면 가입 완료"

## 모바일 고려사항

- Hero 이미지: 세로 비율로 리사이즈
- 가격 카드: 가로 스크롤 또는 세로 스택
- Sticky CTA: 하단 고정 바 (모바일)
- 기능 카드: 2열 → 1열
- 스크린샷: 탭하여 확대 가능

## 기술 구현 참고

### Next.js 라우팅 변경

```
현재:
  page.tsx (/) → SPA 앱 (인증 필수)
  login/page.tsx (/login) → 로그인

변경 후:
  page.tsx (/) → 세션 체크 → 로그인됨: /app 리다이렉트, 미로그인: 랜딩 렌더링
  app/page.tsx (/app) → SPA 앱 (인증 필수)
  login/page.tsx (/login) → 로그인
```

또는 미들웨어에서 처리:
```typescript
// middleware.ts
if (pathname === '/' && !session) → 랜딩 페이지 렌더링
if (pathname === '/' && session) → /app 리다이렉트
```
